# demo: the Canti live console

A presenter console in the app's own look (the 1-bit pixel kit, `../ui/lib/src/theme`): it shows each sound going
from the VOX box's mic through the on-device extractor and BLE into the Canti app, and what the app did with it.
It drives two targets:

| Target | Where the sound goes | What the panels show |
|---|---|---|
| **Screen** (the suite's emulator) | the app's debug feature source (`adb forward` → `localabstract:vox-debug`), as the full feature message with fp1 `features`, `pitch16` and device timing; hold-to-scroll via hold messages | mic frames, extractor output and packet from `web/data/sounds.json`; the app rows are the app's real event log |
| **Phone** (USB, mirrored with scrcpy) | the Pico over USB serial (`send <name>`, `mode ...`), then BLE to the phone. `--phone-direct` injects over adb instead | as above; the app rows are the phone's real event log |

`web/data/sounds.json` is generated by `tools/gen_demo_sounds.py`: the Python extractor's real output (10 ms front-end
frames, fp1, pitch16, the line) on the same synthetic clips the firmware's canned sounds come from
(`firmware/tools/gen_test_sounds.py`). `--check` fails if the lines no longer match `firmware/tests/test_sounds.json`.

```
 web page ──POST /api/cmd──► server.py ──adb──► app debug socket (Screen)
    ▲                            └──serial──► Pico ──BLE──► app (Phone)
    └──── SSE /api/events ◄──── adb logcat -s VOX:I (each target)
```

## Run (Windows, from the repo root)

```powershell
python demo/server.py                  # http://127.0.0.1:8790 ; needs pyserial for the Pico
python demo/server.py --phone-direct   # rehearse the phone target without the Pico
```

- adb: from `PATH`, or scrcpy's bundled `adb.exe` (winget `Genymobile.scrcpy`).
- The emulator runs in WSL (`android/suite/run.sh boot` + `setup`); Windows reaches it as `127.0.0.1:5581`
  (`--emulator` to change). The **Mirror** button opens scrcpy on the current target.
- Regenerate the data after an extractor change: `python demo/tools/gen_demo_sounds.py` (numpy + scipy).

## Recording your own sounds

`tools/record_demo_sounds.py` records your real hums and mouth sounds and writes `web/data/sounds.recorded.json`:
the same schema as `sounds.json` (the Python extractor's real output on your takes), plus `hum_long` (a held hum for
hold-to-scroll and the cursor pitch bar). Needs `python -m pip install --user sounddevice soundfile`.

```powershell
python demo/tools/record_demo_sounds.py --list-devices
python demo/tools/record_demo_sounds.py                          # guided: rise fall arch dip flat pop click hiss clickpop hum_long
python demo/tools/record_demo_sounds.py --device "Microphone Array" --takes 3 --session me   # best SNR of 3 per sound
python demo/tools/record_demo_sounds.py --only rise,pop          # redo some, into the latest session, and rebuild
python demo/tools/record_demo_sounds.py --from demo/recordings/me    # rebuild the JSON only, no mic
python demo/tools/record_demo_sounds.py --from D:/takes          # any folder of <sound>.wav (e.g. from the NixOS box)
```

Per sound: read the instruction, Enter, stay quiet through the 3-2-1 countdown (the extractor measures the room),
make the sound after GO. It prints what the extractor heard (label, line, a pitch16 sparkline, SNR); the right
label is kept automatically, otherwise Enter retries, `k` keeps it anyway, `s` skips. Takes go to
`demo/recordings/<session>/` (private, ignored by git). A skipped or misheard sound is copied from the synthetic set
(`"source": "synthetic"` on that entry); `--keep-mismatch` uses misheard WAVs anyway.

## Keys

| Key | Does |
|---|---|
| `Enter` / `Space` / `Esc` | run the script / one step / stop |
| `1`–`8` | rise fall arch dip flat pop click hiss |
| `Q` / `W` / `E` / `C` | click·click (home) / pop·pop (listen) / rise + held hum / toggle gesture–cursor |
| `H` | hide the operator window |
| `T` | light / dark |

The scripts are in `web/scripts.js`: the same steps every run (`reset`, `shell`, `sound`, `seq`, `hold`, `mode`).
The cursor steps are timed moves, tuned for the emulator's Pixel 6 screen and the article in `WIKI_URL`.
