# app: the VOX companion app (`ai.vox.companion`)

An Android AccessibilityService that turns device feature messages into phone actions. It receives one message per
sound (format in [../PROTOCOL.md](../PROTOCOL.md)) and runs these steps in order:
1. rewrites sounds that match the user's enrolled examples;
2. groups the sounds into sequences;
3. builds the exact state text the model is trained on;
4. decides an action (local rule table or `POST /v1/systemone`);
5. performs the action with gestures or global actions;
6. checks that the screen visibly changed.

The service is written in Kotlin with no dependencies beyond the Kotlin stdlib and the platform APIs. The launcher
screen is the Flutter module in `../../ui`, built in from source (the `:flutter` Gradle project; see ../README.md
"Flutter UI"). The Flutter embedding needs AndroidX, so `android.useAndroidX=true` is set. minSdk is 30 and target is
35. Every step is written to the event log.

## Source files

All files are in `src/main/java/ai/vox/companion/`.

| File | What it does |
|---|---|
| `VoxService.kt` | The AccessibilityService and the pipeline. It sets things up and handles:<br>• feature sources and personalization;<br>• the sequencer;<br>• state building and the decider call (on a worker thread; what the decider settles locally, `Decider.local`, is decided at once on the main thread without the screen walk);<br>• execution and confirmation;<br>• intent cursor mode (target question, highlights, choice by sound);<br>• the debug control ops (`ping`, `config`, `profile`, `screen`, `dump`, `harvest`, `targets`, `pause`, `reset`, `enroll_*`, `fp_floors`, `ble_*`, `device`);<br>• the phone-side pause and `uiStatus()` for the Flutter screen. |
| `Message.kt` | `FeatureMessage`: parses and validates a device message (sounds, labels, mode, armed, `sleeping`, phrase, `timing`, `features`). `SoundLine` reads the fields of a sound line. |
| `Personal.kt` | Personalization:<br>• `SoundFeatures` is the per-sound `fp`, `fp_version` and `pitch16`;<br>• `EnrollmentStore` holds the enrolled custom, ignore and gesture classes per profile, persisted as JSON;<br>• `FpFloors` is the per-feature std floor table, keyed by `fp_version`;<br>• `Matcher` does standardised nearest-neighbour matching (std raised to the floor), banded DTW for contour classes, and per-class leave-one-out reject thresholds;<br>• the line rewrite;<br>• `Personal.localReason` keeps custom and ignore sounds away from the model. |
| `Sequencer.kt` | Groups sounds into sequences. It waits only when a bound longer sequence starts with the sounds heard so far. It uses device timestamps when present and arrival times otherwise. After a prefix acts at once, the rest of a left-out same-action sequence that follows within the gap is absorbed (`hiss click` = one back). |
| `MediaGate.kt` | The phone-mic media lock (user decision 2026-09-27; PROTOCOL.md "Phone microphone", Media lock). While media plays (`isMusicActive`) and `media_lock` is on, a phone/USB mic sound is dropped before the sequencer (`media_gate{kind, source, dropped}`) unless it completes `pop pop`, the unlock; the unlock does nothing else. How the unlock ends is `media_unlock_mode`: `one` (default: the next gesture passes, then it re-locks; `media_unlock_ms`, default 5000, is the time allowed), `fixed` (a window that never extends) or `popext` (a window only another pop pop extends; that pop pop does not listen). The badge shows the pending face while it is open. Media stopping lifts it at once (an `AudioPlaybackCallback` re-checks). Pico sounds never pass through it. |
| `StateBuilder.kt` | `Scene.text()`, the model state, byte-identical to finetune `generate.py`. Also `ScreenContext`, the `screen:` line. |
| `ScreenSummarizer.kt` | `NodeSnap`, a plain copy of an accessibility node, and the classifier that picks the screen kind, media, scroll and keyboard values. |
| `TreeReader.kt` | Reads the active app window into `NodeSnap`s. A subtree is skipped only when its node is invisible and has empty (clipped) bounds: Compose reports its AndroidView holder as invisible although the views inside are visible. Also finds the app root (VOX's own app windows count, so its Flutter screen is readable; its overlays never do) and computes the tree fingerprint the confirmer uses. `targetLayers` gives the cursor the app window plus the app's own windows above it (a floating-button layer), each with the bounds of every window above it (keyboard, system bars, dialogs). Children of nodes that are not visible to the user are skipped. |
| `Decider.kt` | `Decision`, the `Decider` interface (`decide`, and `local`: the same answer when it needs neither the screen nor a model, else null), and `RuleDecider`: the local policy (defaults, profile bindings, phrases, the screen tie-break, cursor mode, not-deliberate sounds). |
| `HttpDecider.kt` | `SystemOneClient` (the `/v1/systemone` choice question), `HttpDecider` (the action question) and `ChainDecider` (`rules`, `model` or `hybrid`, falling back to rules on error). |
| `OllamaDecider.kt` | Decider mode `escalate` (PROTOCOL.md "Decider `escalate`"):<br>• `OllamaClient` is the Ollama `/api/chat` choice question (enum-constrained `format`, `think: false`, temperature 0), with strict parsing, a hard deadline, one call in flight, and `cancel`;<br>• `OllamaDecider` asks the action question;<br>• `EscalatingDecider` keeps bound gestures and settled cases local, sends target picking and the cases the rule table can't settle to the cloud (after the local model, when it is unsure), falls back cloud → local model → rules, never waits behind a newer event, and logs `escalate` events;<br>• `Risk` lists the actions an unscored (cloud) answer must confirm with a pop. |
| `Profile.kt` | User bindings: global, per app, cursor and spoken phrases, plus fixed rules on custom sounds (`my:<name>`). It also produces the rule sentences the model sees and the bound sequences the sequencer waits for (leaving out a sequence whose action is the same as a bound prefix's, so `hiss` never waits for `hiss click`), and those left-out sequences (`absorbedSequences`), whose tail the sequencer absorbs. |
| `Executor.kt` | Performs an action: fling swipes (vertical 72% → 12%, horizontal 85% → 15%, 100 ms, out of the gesture insets; `SwipeGeometry`), taps, pinches, scrolls, global actions (back, home, ...), `forward` (a Forward control, else via the overflow menu), volume, `open_camera`, cursor moves, target taps, and the hold-to-scroll drag (`Executor.Drag`: continued 100 ms strokes, then hold still and lift). Every injected touch stamps `Executor.lastInjectedGestureMs` / `lastInjectedGestureEndMs` (read by the phone mic's touch guard). |
| `Navigation.kt` | Pure helpers for `Executor`: `Forward` (the Forward-control and overflow-menu finder over any node type) and `SwipeGeometry` (fling endpoints clamped out of the system gesture zones). |
| `AutoScroll.kt` | Hold-to-scroll (PROTOCOL.md "Hold messages"): `HoldScrollTrigger` (a `hold start` within 1 s of an executed rise/fall swipe) and `HoldScroller` (scrolls until `hold end`; drops the held flat's final event; 5 s watchdog, 2-minute cap, app-change and screen-off stops). `VoxService.hold()` routes the hold messages and buffers a start that arrives while the swipe is still being decided. |
| `Confirmer.kt` | Decides whether an action visibly changed the screen. It uses accessibility events first, then a masked screenshot grid (`PixelGrid`), and ignores the echo of our own touch. `GrabGate` keeps screenshots 1 s apart (the OS limit): a too-early baseline reuses a recent timeout screenshot or goes without, a too-early timeout screenshot waits. |
| `Overlay.kt` | Accessibility overlays: the floating Canti head (touchable only within its own bounds; drag to move, snaps to a side edge, position remembered per orientation; tap for the pixel menu: Gesture / Cursor / Pause-Resume / sound source), the cursor, and the numbered target highlights. While a Canti screen is in front the head hops into the top-left corner and hides (`tuckBadge`; VoxService tracks resumed activities). |
| `Badge.kt` | The head's face: `BadgeState` (13 states; one-shots vs held), `BadgeFace` (`setState` / `playOnce`; `BadgeFace.create` is the swap point for the animated sprite view), `BadgeStates` (service state and executed actions → states), `BadgeActions` (what the menu calls), and `PlaceholderFace` (the stipple icon at an integer scale, no filtering, with a state strip). |
| `Targets.kt` | Intent cursor mode. Builds `label (role, position)` options from the accessibility tree, the `target` state text, and the answer policy (tap, choose from the top 3, or not on screen). `Occlusion` drops targets hidden by a window above the app or by an in-tree surface (an open drawer, a bottom sheet, a full-screen scrim): hidden = centre covered or under 25% of it visible. Over the option cap, list rows, plain items/images and unlabeled targets are cut before buttons, tabs and fields (so a FAB stays). |
| `FeatureSource.kt` | The `FeatureSource`/`Sink` interfaces, the debug socket (`vox-debug`, adb only), the debug broadcast, and the `PhraseRecognizer` interface (a transcript plus n-best, whatever the engine) with `StubPhraseRecognizer` (`asr_engine` off). |
| `AndroidPhraseRecognizer.kt` | `asr_engine` android: the phone's `SpeechRecognizer`, on-device first, else the default one offline-only; the cloud only with `asr_allow_online`. Asks (API 33+) whether the offline pack is installed. |
| `ListenWindow.kt` | The phrase window: yields the phone mic, starts the recognizer, closes once on a final result, an error or the timeout (+ grace, last partial), resumes the mic once. `AsrPlan`: which recognizer, and the status the user sees (`offline speech pack missing`). |
| `PhraseGrammar.kt` | Spoken phrases to commands, deterministic (PROTOCOL.md "Spoken phrases"): `NumberWords`, `Durations`, navigation variants, `AppMatcher` (open apps), `TargetMatcher` (tap by name), and the n-best choice. Unknown text goes to the phrase decider. |
| `BleLink.kt` | The BLE link without Android (PROTOCOL.md "BLE GATT link (v1)"):<br>• `BleProtocol` holds the UUIDs and the device-side `fragment`, used by tests;<br>• `Reassembler` rebuilds messages from EVENT notifications (first/last bits, counter from 0 per connection, gaps, the 4096-byte limit);<br>• `BleMessages.decode` accepts strict UTF-8 holding one JSON feature message, never a control message;<br>• `BleInfo` parses INFO;<br>• `AuthFailures` counts pairing/encryption failures and words the hint for each kind (stale bond: forget VOX-XXXX; pairing window closed: hold the button 5 s; unknown: both);<br>• `Backoff` computes the reconnect delays. |
| `BleFeatureSource.kt` | The BLE GATT client. It scans by service UUID, connects, requests MTU 517, requests high connection priority, reads INFO, bonds (Just Works), and enables EVENT notifications. It reassembles messages into the same `Sink` (the first message of each link marked `ble-connect`, a reset point for message ids), disarms on disconnect, and reconnects with backoff. After two pairing/encryption failures it stops in `needs_pairing` with a hint for the user. It writes CONFIG for `DeviceLink`, and after a `sleeping` message reconnects quietly (every 2 s, auto-connect, no pairing escalation). Its controls are the `ble_*` ops, and it remembers the device in `ble_device`. |
| `Settings.kt` | SharedPreferences keys and defaults. The API key is never logged. `KeystoreSecrets` stores the cloud key AES-GCM encrypted under an Android Keystore key. |
| `EventLog.kt` | The JSON event log, written to logcat tag `VOX` and to `files/events.jsonl`; also `files/harvest.jsonl`. File writes run in order on their own thread. Listeners (the UI event channel) get each event as it is written. |
| `MainActivity.kt` | The launcher: a `FlutterActivity` showing the `../../ui` status screen. It logs `ui{first_frame}` once per process. |
| `DeviceLink.kt` | The app's view of the device and its commands, without Android: arm/pause/mode/sleep CONFIG writes on a ready link, one at a time, confirmed by the device's next no-sound state message, failed at once when that reply carries `rejected`, or failed after 1.5 s with no reply (`device_cmd` events); asleep/awake tracking from `sleeping`; the device's `presence()` for the status screen; the pairing-failure count and hint. |
| `UiBridge.kt` | The platform channels between the Flutter screen and the service (`ai.vox/backend`, `ai.vox/events`; PROTOCOL.md "UI channel"), including `deviceCommand` (answered when the device confirms or the command fails), `connectDevice`, and the pairing screen's `requestBluetooth` / `enableBluetooth` / `openAppSettings` / `launchRoute` (and `openRoute` to a running UI). |
| `Pairing.kt` | The first-run pairing screen's entry: `openIfNoDevice` (badge menu, sound-source chooser) opens MainActivity with route `pair` when the Pico is the source and no device is remembered. |
| `LegacySettingsActivity.kt` | The old native settings screen, opened from the status screen's **Legacy settings** button: decider mode, model endpoint, API key, the auto-scroll speed, the cloud endpoint, model and key for `escalate` (with **Test connection** and **Clear cloud API key**), a link to accessibility settings, and the **Allow Bluetooth (VOX device)** permission button. |
| `Vocab.kt`, `TargetVocab.kt` | **Generated** by `../tools/gen_vocab.py` from `finetune/vox`. Do not edit by hand. |
| `audio/VxNative.kt` | JNI binding to `libvx_jni.so`, the Pico's C++ extractor (`firmware/extract/src`, compiled as is): create/destroy, `pushDirect`/`pushShorts`/`pushFloats` returning 0..n message strings, `flush`, `reset`, `stats` (per-hop timing, level, 8-band level, floor). |
| `audio/MicCapture.kt` | The audio thread: `AudioRecord` (16 or 48 kHz mono, UNPROCESSED or VOICE_RECOGNITION, AGC/NS/AEC off), preferred device, blocking reads into one direct buffer handed to the extractor in place, the frame-0 clock from `AudioTimestamp`, a once-a-second stats snapshot (hop times, level, thread CPU). |
| `audio/PhoneMicSource.kt` | Feature source `phone-mic`: applies `SourcePolicy`, starts/stops the foreground service and the capture, follows USB plug/unplug, turns native sounds into protocol messages on the main thread, and serves the `mic_status`/`mic_level`/`mic_feed` ops. |
| `audio/PhoneGate.kt` | The phone-mic media gate, pure and JVM-tested: while media plays (`mic_media_gate`), a pop/click under 14 dB over the floor or a hum under 14 dB / clarity 0.8 becomes `unknown`; and the media-hiss rule (2026-09-27): while media plays on the phone's speaker, a phone/USB hiss with `centroid_hz` over `hiss_media_max_centroid_hz` (6500, 0 = off) becomes `unknown`, reason in `mic_sound.gated`. Never for the Pico. |
| `audio/SourcePolicy.kt`, `audio/PhoneMessages.kt`, `audio/MicSettings.kt` | Pure parts, JVM-tested: what runs for each source and app state; native sound → the Pico's feature message (and hold messages); the `sound_source`/`mic_*` settings. |
| `audio/SoundSource.kt` | The one API for switching the sound source (settings screen, notification, floating badge): `get`, `set`, `choose`, `next`, `label`, `micState`, listeners. |
| `audio/MicListenService.kt`, `audio/CantiNotification.kt` | The `microphone` foreground service (only while a mic source is picked) and Canti's status notification for every source (mode, Pause/Resume, Source buttons). |
| `audio/SoundSourcePanel.kt`, `audio/SourceChooserActivity.kt` | The **Sound source** block (settings screen) with the mic permission request, and the same block as a small dialog for the notification's **Source** button. |
| `../cpp/vx_jni.cpp`, `../cpp/CMakeLists.txt` | (in `src/main/cpp`) The JNI glue (one mutex: the extractor keeps static scratch; the compact `gate` object per sound; the 8-band level summed from the extractor's per-hop spectrum for `stats`) and its NDK build of `firmware/extract/src` (`-O2 -ffp-contract=off`, arm64-v8a and x86_64). |

## Commands

Run these from `android/`.

```sh
./dev bash -c 'cd ../ui && flutter pub get'       # once, and after ui/pubspec.yaml changes: generates ui/.android/include_flutter.groovy
./dev gradle assembleDebug                         # app/build/outputs/apk/debug/app-debug.apk
./dev gradle :app:testDebugUnitTest                # JVM tests (516 on 2026-09-28; per class in app/build/test-results/testDebugUnitTest)
./dev gradle :app:testDebugUnitTest --tests 'ai.vox.companion.PersonalTest'
./dev python3 tools/gen_vocab.py --check           # fail if Vocab.kt / TargetVocab.kt are stale
suite/run.sh test                                  # the emulator tests (see ../suite/README.md)
```
